# Stage 6 Safe Outbound HTTP and Webhooks

Stage 6 adds the shared SSRF-safe outbound HTTP layer and environment-scoped
webhooks.

## Safe outbound HTTP

All webhook delivery goes through `SafeOutboundHttpClient`.

Webhook policy:

- HTTPS only
- port 443 only
- no redirects
- 10 second timeout
- 64 KB response read cap
- 16 KB stored response preview
- localhost, `.localhost`, GCP metadata hosts, private IPv4 ranges, loopback,
  link-local, multicast, and equivalent IPv6 ranges are blocked

The guard resolves DNS and the HTTP handler connects to the validated address so
DNS rebinding cannot swap in a private address after validation.

## Webhook signing

Webhook endpoint creation returns a show-once signing secret:

```text
dwhsec_...
```

The secret is stored encrypted with ASP.NET Data Protection. Deliveries include:

```text
X-DevControl-Webhook-Id
X-DevControl-Event
X-DevControl-Delivery
X-DevControl-Timestamp
X-DevControl-Signature
```

`X-DevControl-Signature` is:

```text
sha256=<hmac_sha256(secret, "<unix_timestamp>.<delivery_id>.<raw_json_body>")>
```

## Events

Stage 6 supports:

```text
webhook.test
app.registered
api_key.created
api_key.revoked
api_key.rotated
feature_flag.created
feature_flag.updated
```

Webhook payloads include resource IDs, actor metadata, and safe operational
details such as API key prefixes. They do not include API key secrets,
registration tokens, or webhook signing secrets.

## Delivery and retries

Delivery status is stored in:

```text
webhook_events
webhook_deliveries
webhook_delivery_attempts
```

Retryable failures are network errors, timeouts, HTTP `408`, HTTP `429`, and
HTTP `5xx`. Each delivery is capped at 5 attempts with backoff:

```text
1 minute, 5 minutes, 15 minutes, 1 hour, 6 hours
```

The internal scheduler endpoint runs bounded retry batches:

```text
POST /internal/scheduler/tick
X-DevControl-Scheduler-Secret: ...
```

Terraform creates one Cloud Scheduler job every 5 minutes. The scheduler secret
is generated by Terraform, stored in Secret Manager, exposed to Cloud Run as
`DEVCONTROL_SCHEDULER_SECRET`, and sent by the Scheduler job as a header.

## Live proof

Stage 6 is complete only after the code is pushed and live on GCP.

Expected proof:

1. GitHub CI and deploy workflow succeed.
2. Cloud Run `/health/live` and `/health/ready` return success.
3. A public HTTPS receiver gets a signed `webhook.test` delivery.
4. A real DevControl mutation, such as `feature_flag.updated`, creates and
   delivers a webhook event.
5. A controlled failing receiver response creates a retry and the bounded retry
   batch succeeds or exhausts as expected.
6. Private/internal URLs such as `https://127.0.0.1/...` are blocked.
7. PostgreSQL readback shows endpoint, event, delivery, and attempt rows.
